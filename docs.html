Aeon Framework Documentation

The definitive technical manual for the Aeon Neuro-Symbolic Agent Framework. Covers Kernel v0.3.0.

Introduction

Aeon is not just another LLM wrapper. It is a Neuro-Symbolic Operating System designed for high-consequence environments. Unlike purely probabilistic agents (like LangGraph or AutoGPT), Aeon introduces a deterministic Executive Layer that enforces safety invariants ("Axioms") over the LLM's stochastic outputs.

Why Aeon?
Most frameworks are "Think -> Act". Aeon is "Think -> Verify -> Act". This makes it suitable for industrial, aerospace, and medical applications where hallucination is unacceptable.

Installation

Aeon requires Python 3.10+ and a supported OS (Linux, macOS, Windows WSL).

BASH
# 1. Create a virtual environment
python -m venv venv
source venv/bin/activate

# 2. Install Aeon Core from PyPI
pip install aeon-core

# 3. Install browser dependencies (for BrowserTool)
playwright install

# 4. Verify installation
aeon doctor

Example: Personal (Journal Assistant)

Using the Capability system to extend the agent. The JournalCapability manages local filesystem persistence while the Cortex provides emotional reflection.

PYTHON AGENT EXTENSION
class JournalCapability(Capability):
    async def save_entry(self, text: str) -> str:
        date = datetime.date.today().isoformat()
        entry = f"\n[{date}]\n{text}\n"
        with open(self.journal_file, "a") as f:
            f.write(entry)
        return f"✅ Entry saved for {date}"

# Agent setup with extension

def no_personal_data(response: str):

Architecture Overview

The Aeon Kernel orchestrates 16 integrated subsystems. This "Battery-Included" approach ensures you don't need to glue together 10 different libraries to get a production-ready agent.

The 16 Kernel Subsystems

Subsystem Description
Cortex Reasoning Engine. Interfaces with LLMs (Ollama, OpenAI) to generate Plans.
Executive Safety Layer. Enforces deterministic Axioms to specific actions.
Synapse Tool Interface. Handles MCP (Model Context Protocol) and Native Tools.
Memory Event-Sourced storage (`EventMemory`) for full audit trails.
Dispatcher Internal pub/sub event bus for decoupled communication.
Automation Background task scheduler with Cron/Interval support.
Gateway FastAPI-based HTTP/WebSocket server for external access.
Security Authentication (API Keys, JWT) and TrustLevel enforcement.
Routing Pattern-matching message router.
Economics Token usage tracking and cost estimation (`pricing.py`).
Observability Lifecycle hooks (`hook.py`) for monitoring.
Health System diagnostics and heartbeat.
Hive Agent-to-Agent (A2A) protocol.
Integrations Platform adapters (Slack, Discord).
Extensions Pluggable "Skills".
CLI Command-line entry points.

Cortex (Reasoning)

The Cortex (`src/aeon/cortex/reasoning.py`) is the brain. It abstracts the LLM provider (System 1) and normalizes outputs into structured Plans.

PYTHON
from aeon.cortex.reasoning import Cortex, CortexConfig

# Initialize with local Ollama or Cloud Model
config = CortexConfig(
    model="ollama/llama3",  # or "google/gemini-2.0-flash"
    temperature=0.0       # Deterministic sampling
)
cortex = Cortex(config)

# Plan an action
plan = cortex.plan_action(
    system_prompt="You relate strict facts.",
    user_input="Check the reactor temperature.",
    tools=[...]
)

Memory (Event Sourcing)

Aeon uses Event Sourcing (`src/aeon/memory/events.py`). State is derived from an append-only log of events. This is crucial for Safety Critical debugging.

Event Types

  • AgentStartEvent: Boot sequence.
  • ReasoningStepEvent: Chain-of-thought log.
  • ToolExecutionEvent: Critical. Arguments passed to tools.
  • ToolResultEvent: Output or Error from tools.
  • AxiomViolationEvent: Recorded when Safety Layer blocks an action.

Automation (Scheduler)

The TaskScheduler (`src/aeon/automation/scheduler.py`) allows agents to be proactive, not just reactive. Tasks run in the background (asyncio).

PYTHON
# Schedule a daily check
await agent.automation.schedule(
    task_id="monitoring_sweep",
    handler_id="run_diagnostics",
    cron="0 9 * * *"  # 9:00 AM Daily
)

# Schedule a heartbeat every 30s
await agent.automation.schedule(
    task_id="heartbeat",
    handler_id="ping_home",
    interval_seconds=30
)

Gateway & Security

The Gateway (`src/aeon/gateway/gateway.py`) exposes the agent via HTTP. Security (`src/aeon/security/auth.py`) handles bearer tokens and API keys.

Production Note
Always enable enable_encryption=True in production to enforce TLS/SSL termination at the Gateway level.

Authentication Providers

Aeon supports pluggable Auth Providers extending AuthProvider.

  • APIKeyAuthProvider: For machine-to-machine (M2M) communication.
  • BearerTokenProvider: For user sessions (JWT-like).

Safety: Axioms

Axioms (`src/aeon/executive/safety.py`) are deterministic Python functions that intercept LLM Actions before execution. They act as "Guardrails with Teeth".

PYTHON DEFINING AN AXIOM
from aeon.executive.safety import AxiomViolationError

def no_delete_axiom(payload: dict):
    """Prevents the agent from deleting files."""
    tool_name = payload.get("tool_name")
    
    if tool_name == "fs_delete":
        # BLOCK the action immediately
        raise AxiomViolationError("Deletion is prohibited by Safety Policy A-12.")
    
    if tool_name == "fs_write":
        # SANITIZE the input (Modify on the fly)
        if "password" in payload["args"]["content"]:
             payload["args"]["content"] = "[REDACTED]"
             return payload  # Return modified dict
             
    return True # ALLOW

Safety: TMR (Triple Modular Redundancy)

For aerospace compliance (DO-178C), single-model decisions are insufficient. TMR involves running 3 distinct agents (Models A, B, C) and voting on the outcome.

PYTHON TMR VOTER PATTERN
async def execute_with_tmr(prompt):
    # 1. Parallel Execution
    results = await asyncio.gather(
        agent_gpt4.cortex.plan(prompt),
        agent_claude3.cortex.plan(prompt),
        agent_gemini2.cortex.plan(prompt)
    )
    
    # 2. Consensus
    consensus = vote(results)
    
    if not consensus:
        raise SafetyShutdown("TMR Dissensus: Models disagree on critical action.")
        
    return consensus

CLI Reference

The `aeon` command line tool manages the lifecycle.

`aeon init`

Creates a new project structure.

aeon init my_agent --template default

`aeon serve`

Starts the Gateway server.

aeon serve --config ./aeon.yaml --port 8000 --reload

`aeon run`

Executes a one-off instruction.

aeon run "Analyze the logs in /var/log/syslog" --trust-level=RESTRICTED

Configuration (YAML)

agent:
  name: "Sentinel-01"

  port: 8000
  max_connections: 1000
  enable_encryption: true

  enabled: true
  tasks:
    - id: "cleanup"
      cron: "0 0 * * *"
      handler: "cleanup_logs"
