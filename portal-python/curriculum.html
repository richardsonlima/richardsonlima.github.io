Por que esta ordem?

Princípio 01
Modelo de objetos antes de tudo
Nomes que apontam para objetos, mutabilidade, hashing e o custo de cada coleção explicam 80% dos bugs estranhos em Python. Sem essa base, patterns e performance viram receita decorada.
Princípio 02
Idiomas antes de padrões
Iteradores, decorators, context managers e o data model são as ferramentas com que o Python implementa padrões. Quem conhece os idiomas percebe quando um padrão do GoF vira uma função de três linhas.
Princípio 03
Testes e tipos antes de arquitetura
Clean Code, pytest e tipagem estática são a rede de segurança que permite refatorar. Arquitetura sem testes é diagrama, não sistema.
Princípio 04
Princípios antes de catálogos
SOLID, acoplamento e coesão explicam POR QUE cada padrão existe. Com os princípios na cabeça, os 23 padrões do GoF e os arquiteturais deixam de ser lista e viram consequência.
Princípio 05
Medir antes de otimizar
Concorrência e performance vêm depois do design porque otimizar código mal estruturado é cimentar o problema. Profiling primeiro, depois algoritmo, memória, vetorização e código nativo.
Princípio 06
Dados e produção como síntese
Large data e produção juntam tudo: formatos colunares, engines vetorizadas, paralelismo, arquitetura e observabilidade. Pratique em paralelo desde a etapa 1, com um projeto real.
